# Human Judgment Checklist for AI-Assisted Work

Use this before shipping any AI-assisted artifact.

AI can help create the work. The human still owns the judgment.

---

# 1. Understanding Check

```markdown
[ ] I understand the issue well enough to defend this without AI.
[ ] I can explain the recommendation in plain language.
[ ] I know which facts are confirmed.
[ ] I know which points are assumptions.
[ ] I know which areas remain uncertain.
[ ] I know what would change the recommendation.
```

---

# 2. Audience Fit

```markdown
[ ] The output is written for the actual audience.
[ ] The audience's likely objections are addressed.
[ ] The level of detail is appropriate.
[ ] The tone matches the situation.
[ ] The format is usable by the intended reader.
[ ] The most skeptical reader would understand the logic.
```

---

# 3. Decision Usefulness

```markdown
[ ] The problem is clear.
[ ] The recommendation is clear.
[ ] The decision required is clear.
[ ] Options and trade-offs are visible.
[ ] Risks are explicit.
[ ] Dependencies are explicit.
[ ] Owners are named where possible.
[ ] Next steps are concrete.
[ ] Timing is clear.
[ ] The output helps someone act.
```

---

# 4. Source Discipline

```markdown
[ ] Facts are separated from interpretations.
[ ] Interpretations are separated from recommendations.
[ ] Unsupported claims have been removed or flagged.
[ ] Data points are traceable to a source.
[ ] No external facts were introduced unless allowed.
[ ] No invented details remain.
[ ] Uncertain claims are marked as assumptions or low confidence.
[ ] Conflicting information is identified.
```

---

# 5. Enterprise IT Quality Check

```markdown
[ ] System ownership is clear.
[ ] Process ownership is clear.
[ ] Data ownership is clear.
[ ] Integration dependencies are identified.
[ ] Security implications are considered.
[ ] Compliance implications are considered.
[ ] Support model implications are considered.
[ ] Change-management implications are considered.
[ ] Operational impacts are considered.
[ ] Reporting / analytics impacts are considered.
```

---

# 6. Risk Check

```markdown
[ ] The most likely failure mode is identified.
[ ] The most damaging failure mode is identified.
[ ] The recommendation includes risk mitigations.
[ ] Risks are not hidden in vague language.
[ ] Residual risks are visible.
[ ] Escalation points are clear.
[ ] Decision gates are clear.
```

---

# 7. Clarity Check

```markdown
[ ] The opening paragraph states the point.
[ ] The structure is easy to scan.
[ ] The language is direct.
[ ] There is no generic filler.
[ ] There are no unnecessary adjectives.
[ ] There are no vague phrases such as "leverage synergies" or "drive transformation" unless explicitly defined.
[ ] Long paragraphs have been shortened.
[ ] Tables are used where they improve comprehension.
[ ] The final version is shorter and sharper than the first draft.
```

---

# 8. AI Artifact Check

```markdown
[ ] The work does not sound like a generic AI draft.
[ ] Repetitive phrasing has been removed.
[ ] Over-explaining has been cut.
[ ] Claims are not overstated.
[ ] The output reflects the real stakeholder context.
[ ] The document contains specific operational details.
[ ] No fabricated examples, numbers, names, or timelines remain.
```

---

# 9. Final Pass

Before sending, answer these questions:

```markdown
1. Would I present this in a leadership meeting?
2. Would the target stakeholder recognize their reality in this?
3. Can someone execute on this Monday morning?
4. Does this make the next conversation easier?
5. Is the recommendation defensible?
```

---

# 10. Ship / Revise Decision

```markdown
Decision:
[ ] Ship
[ ] Revise
[ ] Needs source validation
[ ] Needs stakeholder input
[ ] Needs executive decision
[ ] Needs technical review
[ ] Needs risk / compliance review
```
